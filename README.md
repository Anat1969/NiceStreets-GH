# הרחובות הטובים של אשדוד — Good Streets Ashdod

אפליקציית שיתוף ציבור (PWA) בעברית, mobile‑first, לאגף אדריכלות העיר בעיריית אשדוד
(Ashdod, Israel). תושבים לומדים מה הופך רחוב לטוב, בוחרים רחוב, מדרגים אותו בשבע שאלות,
מנמקים, מעלים תמונה — ועוקבים אחרי הסטטוס העירוני שהעירייה מעדכנת בגלוי.

המימוש נגזר מהאפיון שבמסמך "הרחובות הטובים של אשדוד — אפיון ופרומפט לבנייה".

## הרצה מקומית

```bash
npm install
cp .env.example .env.local     # קבעו STAFF_CODE
npm run dev                    # http://localhost:3000
```

בלי משתני Supabase האפליקציה עובדת מלאה מול מאגר JSON מקומי בתיקייה `.data/`
(מתעלמים ממנה ב‑git). זו ברירת המחדל לפיתוח ולהדגמה.

### נתוני הדגמה

היכנסו ל‑`/admin` עם ה‑STAFF_CODE ולחצו "הוספת נתוני הדגמה". הנתונים מסומנים
`is_demo` בנפרד מקולות אמיתיים, וניתן למחוק אותם בלחיצה אחת לפני פתיחה לציבור.

## הכתובת הציבורית והפריסה

האפליקציה פרוסה ב-Vercel. הפריסה מושכת אוטומטית מענף `main` במאגר.

### משתני הסביבה שצריך להגדיר ב-Vercel

| משתנה | ערך |
|---|---|
| `STAFF_CODE` | סיסמה לבחירתך, לכניסת הצוות ל-`/admin` |
| `SUPABASE_URL` | `https://cbhexpybdggwzyakgagd.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | מפתח הגישה למסד הנתונים |

אחרי הגדרת המשתנים צריך Redeploy כדי שייכנסו לתוקף.

לגבי המפתח יש שתי אפשרויות:

1. **מפתח anon** — מפתח שאינו סודי מעצם הגדרתו. הוא עובד כי הוגדרו ב-RLS
   הרשאות כתיבה מדויקות לתפקיד `anon` (ראו את סוף `supabase/schema.sql`).
   פעולות הצוות מוגנות ב-`STAFF_CODE` ברמת האפליקציה. מתאים ל-MVP ולשיתוף
   עם מכרים.
2. **מפתח service_role** — הדרך המקובלת לייצור. מעתיקים אותו מ-Supabase:
   Project Settings → API keys → service_role. **מפתח סודי**: רק כמשתנה סביבה
   ב-Vercel, אף פעם לא בקוד. אחרי המעבר אליו אפשר למחוק את מדיניות ה-`anon`
   שבסוף הסכמה.

בשני המקרים שם המשתנה זהה, והמפתח נקרא בשרת בלבד ואינו נשלח לדפדפן — ולכן שמו
אינו מתחיל ב-`NEXT_PUBLIC_`.

### למה Supabase ולא אחסון ב-Vercel

ב-Vercel מערכת הקבצים אינה קבועה: כל פריסה מחדש או הפעלה מחדש של הפונקציה מוחקת
קבצים. לכן מאגר ה-JSON המקומי מתאים רק לפיתוח. כשמוגדרים משתני Supabase
האפליקציה עוברת אוטומטית ל-Postgres, והנתונים נשמרים — כולל תמונות, שנשמרות
בטבלה `photo_blobs` כטקסט base64, כך שכל מסד הנתונים הוא יחידה אחת לגיבוי
ולשחזור.

## ארכיטקטורה

- **ממשק:** Next.js 15 (App Router) + TypeScript + Tailwind 4, RTL מלא, PWA.
- **מפה:** MapLibre GL עם מפת רקע OpenStreetMap ללא מפתח API
  (`tiles.openfreemap.org`), תוויות בעברית היכן שקיימות, ונפילה אוטומטית לרקע
  ריק אם מפת הרקע אינה זמינה — שכבות הקולות ממשיכות להיות מוצגות. להחלפה במפת
  רקע עירונית: `NEXT_PUBLIC_MAP_STYLE` לכתובת style.json.
- **נתונים:** שכבת אחסון מופשטת ב‑`lib/store/`. שני מימושים לאותו ממשק:
  - `LocalStore` — קובץ JSON ב‑`.data/`, לפיתוח בלבד.
  - `SupabaseStore` — Postgres, נכנס לפעולה כשמוגדרים `SUPABASE_URL` ו‑
    `SUPABASE_SERVICE_ROLE_KEY`. זהו האחסון הקבוע בייצור.
- **הרשאות:** הדפדפן אינו פונה ל‑Supabase ישירות; כל בקשה עוברת דרך route handler
  ב‑Next.js שמאמת הרשאה. ה‑RLS ב‑`supabase/schema.sql` הוא קו הגנה שני.
- **קונפיגורציית עיר:** הכול מרוכז ב‑`lib/city.ts` — רובעים, רשימת רחובות,
  טיפולוגיות, קריטריונים, סטטוסים, צבעים וטקסטים. עיר אחרת מחליפה את הקובץ הזה בלבד.

### מודל הנתונים

`quarters`, `streets`, `votes`, `photos`, `street_status` — בדיוק כפי שהוגדר באפיון.
קול אחד לכל משתמש לכל רחוב (`unique (user_id, street_id)`); הצבעה חוזרת מעדכנת את
הקול הקודם ואינה מוסיפה קול חדש.

### פרטיות

- אין שמירת שם, טלפון או דוא"ל. המשתמש מזוהה במזהה אנונימי בעוגייה בלבד.
- התמונה מוקטנת ל‑1200px ומקודדת מחדש ל‑JPEG בדפדפן. הקידוד מחדש מוחק את כל שדות
  ה‑EXIF, כולל מיקום GPS.
- תמונה מתפרסמת רק אחרי אישור ידני של הצוות; עד אז היא גלויה לצוות בלבד.

## Supabase

הפרויקט בשימוש: `ASHDODMAP` (ref `cbhexpybdggwzyakgagd`), אזור ap-southeast-1.
הסכמה, ה-RLS ונתוני הייחוס (18 רובעים, 14 רחובות) כבר הוחלו עליו.

להקמה מחדש או למעבר לפרויקט אחר:

```bash
psql "$DATABASE_URL" -f supabase/schema.sql
```

הסכמה כוללת PostGIS, אילוצים, RLS לכל הטבלאות ואחסון תמונות בטבלה. חברי צוות
נוספים נרשמים בטבלת `staff` דרך ה-service role או מלוח הבקרה של Supabase; אי
אפשר להוסיף את עצמך דרך ה-API.

## התאמה לעיר אחרת

כל מה שמזהה את אשדוד יושב בשני מקומות בלבד:

| מה | איפה |
|---|---|
| שם העיר, מרכז המפה, זום, שם האגף, טקסטים פותחים | `lib/city.ts` — האובייקט `CITY` |
| רובעים, טיפולוגיות, שבע השאלות, 12 הקריטריונים, סטטוסים, דוגמאות | `lib/city.ts` |
| רשימת הרחובות | `data/ashdod-streets.json`, נבנית מקובץ המקור |
| שיוך רחוב לרובע | `data/ashdod-street-quarters.csv`, ואז `npm run assign:quarters` |
| שיוך רחוב לסוג | ממסך הצוות |
| צבעים ומרווחים | `app/globals.css` — משתני ה-CSS ב-`:root` |

הקוד עצמו אינו יודע דבר על אשדוד. להקמת עיר אחרת: להחליף את `CITY`
ואת `QUARTERS`, לבנות רשימת רחובות מאותו קובץ ארצי עם שם עיר אחר
(`CITY_NAME` ב-`scripts/build-street-list.mjs`), ולמקם את הרובעים
ממסך הכיול.

## מקורות הנתונים

| מה | מקור | קובץ |
|---|---|---|
| רשימת הרחובות | data.gov.il — רשימת רחובות בישראל, קובץ עם סינונימים | `data/source-streets-israel-ashdod.csv` |
| רשימה קנונית לאפליקציה | נבנית מהקובץ שמעל | `data/ashdod-streets.json` |

לבנייה מחדש אחרי עדכון המקור:

```bash
node scripts/build-street-list.mjs data/source-streets-israel-ashdod.csv > data/ashdod-streets.json
```

הרשימה מכילה 682 רחובות רשמיים באשדוד ו-875 שמות נרדפים. כל איות שתושב יכתוב
נפתר לרחוב אחד דרך `lib/street-name.ts`, שמטפל בקידומות (רחוב, שד', דרך),
בגרש ובגרשיים על כל צורותיהם, וגם בסדר מילים הפוך ("בגין מנחם" מול "מנחם בגין").

**רובע וסוג רחוב אינם ברישום הארצי.**

הרובע מגיע מרשימת העירייה, `data/ashdod-street-quarters.csv` (שם רחוב, רובע).
`npm run assign:quarters` מצליב אותה מול המרשם הארצי, כותב את
`lib/street-quarters.generated.ts` שממנו נבנה `STREET_ASSIGNMENTS`, ומדווח
בקובץ `data/ashdod-street-quarters.unmatched.csv` על כל שם שלא נמצא במרשם ועל
כל סתירה. שם שלא נמצא נשאר בלי רובע — לעולם לא בניחוש.

סוג הרחוב נקבע על ידי הצוות במסך לוח הבקרה. רחוב שטרם שויך מוצג כ"טרם שויך
רובע" או "טרם שויך סוג".

מלבד הרובעים הממוספרים, הרשימה כוללת אזורים שאינם רובע: הקריה (הסיטי), מע"ר
דרום, המרינה, אזורי התעשייה, עורף הנמל, ו"צירים ראשיים חוצי עיר" — שדרות
שעוברות בכמה רובעים. כולם נשמרים כרובעים כדי שאף רחוב לא יאבד את הסיווג שלו,
והקופסה שלהם במפה סכמטית כמו כל השאר.

לאיחוד רשומות קיימות אחרי שינוי במקור:

```bash
node scripts/dedupe-streets.mjs streets.json --sql
```

הסקריפט מדפיס דוח בעברית ואת ה-SQL לביצוע, ואינו ממזג שום שם שאינו מזוהה
ברישום — כזה מדווח עם הצעות קרובות להחלטת הצוות.

## אימות נתוני GIS — לפני עלייה לאוויר

הגבולות של הרובעים, המרכזים שלהם ורשימת הרחובות שב‑`lib/city.ts` הם **נתוני
הדגמה סכמטיים**, ומסומנים ככאלה גם בקוד וגם בממשק. לפני פתיחה לציבור יש להחליף
אותם בשכבות ה‑GIS העירוניות:

```bash
npm run import:gis -- quarters.geojson streets.geojson > city-data.json
```

הסקריפט (`scripts/import-gis.mjs`) ממיר FeatureCollection לצורה ש‑`lib/city.ts`
מצפה לה, מסמן כל רחוב מיובא כ‑`verified: true`, ומדווח על רובעים או טיפולוגיות
שאינם מזוהים. שמות השדות הצפויים מתועדים בראש הסקריפט וניתנים להתאמה.

נושאים נוספים לאימות לפני עלייה לאוויר: מדיניות פרטיות ומדיניות תמונות (פנים
ולוחיות רישוי), ומי בצוות מעדכן סטטוסים ובאיזו תדירות. כמו כן, ניסוח 12
הקריטריונים כאן מבוסס על עקרונות מחקר "רחובות טובים" של מינהל התכנון ויש לאמת
אותו מול המסמך הרשמי.

## זיהוי

- **תושב/ת:** מזהה אנונימי בעוגייה, נוצר אוטומטית בהצבעה הראשונה.
- **צוות:** קוד צוות (`STAFF_CODE`) בעמוד `/admin`. מספיק ל‑MVP; לייצור מומלץ
  לעבור ל‑Supabase Auth עם קוד SMS ולטבלת `staff`, כפי שהסכמה כבר תומכת.

## תצוגה — מחשב ונייד

פריסה אחת, שני מצבים. בנייד: ניווט תחתון ועמודה צרה. במחשב: ניווט צדי,
טבלאות רחבות, והמפה לצד רשימת הרחובות.

בכותרת יש מתג **אוטומטי / תצוגת מחשב / תצוגת נייד**. הבחירה נשמרת בעוגייה
ולא רק בדפדפן, כך שהשרת מגיש את הפריסה הנבחרת כבר בטעינה הראשונה במקום
להחליף אחריה. "תצוגת מחשב" נשארת תצוגת מחשב גם במסך צר: הדף נגלל לצדדים
במקום לכווץ את המפה.

## נגישות

הועבר סבב מדידה, לא הערכה:

- **ניגודיות:** כל צירופי הטקסט והרקע בשימוש נמדדו. הנמוך ביותר הוא 4.56:1,
  מעל הנדרש ל-AA. שני צבעים הוכהו בעקבות המדידה: `ink-faint` מ-`#7c8a99`
  ל-`#5e6c7b` (היה 3.0–3.5 בטקסט של 13px), ו-`warm` מ-`#b8742a` ל-`#a25e14`
  כדי שגם טקסט לבן על התג יעבור.
- **סולם הדירוג:** 8:1 ומעלה על כל עשרת הרקעים, והצבע לעולם אינו הסימן
  היחיד — כל צעד נושא גם מילה.
- **גדלי מגע:** כל כפתור, שדה וקישור-בקרה בגובה 44px לפחות. קישור בתוך
  טקסט רץ שומר על גובהו הטבעי.
- **מבנה:** כותרת h1 אחת בכל מסך ותת-כותרות h2 מתחתיה, `lang="he"`,
  `dir="rtl"`, קישור דילוג לתוכן, `aria-current` בניווט, `aria-sort`
  בטבלאות, `role="status"` להודעות ו-`role="alert"` לשגיאות.
- **תמונות:** תמונות קישוט מסומנות ב-`alt` ריק כדי שקורא מסך לא יקריא
  אותן פעמיים; תמונות תוכן נושאות תיאור.

הבדיקות מורצות אוטומטית על חמשת המסכים הציבוריים ומדווחות אפס ממצאים.

## בדיקות שבוצעו

`npm run typecheck` ו-`npm run build` עוברים.

**נבדק מקצה לקצה בדפדפן**, מול האחסון המקומי: זרימת ההצבעה בשלושה שלבים,
עדכון קול קיים, שלושה איותים של אותו רחוב שיוצרים רשומה אחת, העלאת תמונה,
אישור ודחייה, תור התמונות, שיוך רחוב לרובע ולסוג על ידי הצוות, כיול רובע
על המפה, סינון ומיון והתאמת הייצוא אליהם, וארבעת מצבי התצוגה.

**נבדק ברמת מסד הנתונים** מול Supabase: הסכמה, האילוצים, ה-RLS, וכל
פעולות האפליקציה בהרצה תחת תפקיד `anon`.

**נבדק חישובית:** ניגודיות כל צירופי הצבעים בשימוש, וסבב נגישות אוטומטי
על חמשת המסכים הציבוריים.

**לא נבדק מכאן:** האתר החי עצמו ואריחי מפת הרקע — רשת סביבת הפיתוח חוסמת
`*.vercel.app` ו-`tiles.openfreemap.org`. מצב הפריסה, הגדרות הסביבה ומסד
הנתונים כן נבדקים.

אין עדיין בדיקות אוטומטיות שמורות בריפו; הבדיקות הורצו כסקריפטים חד-פעמיים.
