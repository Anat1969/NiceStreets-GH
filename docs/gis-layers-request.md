# שכבות GIS שחסרות לאפליקציה: בקשה לאגף ה-GIS

**הרחובות הטובים של אשדוד** בודקת כל רחוב ב-**12** קריטריונים, בארבע שכבות: שלד, חתך, דופן, מרקם ואקלים.
==בלי השכבות שלמטה, מנוע הבדיקה מסמן "אין נתון" ולא נותן ציון.== נתון חסר לעולם לא הופך לציון נמוך.

עודכן: 29.10.2026. מקור הצורך: `data/audit-criteria.json` ו-`lib/city.ts`.

## פורמט

- **GeoJSON**, או Shapefile / File Geodatabase. כל פורמט מומר אצלנו.
- **מערכת קואורדינטות:** רשת ישראל החדשה (ITM, EPSG:2039) או WGS84 (EPSG:4326). לציין איזו.
- **שדה מקשר:** סמל רחוב לפי מרשם הלמ"ס בכל שכבה שקשורה לרחוב. בלי זה, החיבור נעשה לפי שם, ושמות נכתבים בכמה צורות ("שד' הרצל", "שדרות הרצל").
- **תאריך עדכון לכל שכבה.** המנוע מתריע על נתון בן יותר מ-**3** שנים, או בלי תאריך.
- **הרשאת שימוש:** האם מותר להציג את השכבה לציבור באפליקציה, או לצוות בלבד.

## נוסח קצר לשליחה

> שלום,
> לאפליקציית "הרחובות הטובים של אשדוד" של אגף אדריכלות העיר דרושות שכבות GIS לחישוב מדדי הרחוב.
> בעדיפות ראשונה: קווי אמצע רחובות (עם סמל רחוב), גבולות רובעים מלאים כולל רובע ז' ורובע י"ד, מגרשים (גוש, חלקה, ייעוד), תחום הדרך, מדרכות, ומבנים עם גובה או מספר קומות.
> בעדיפות שנייה: סקר עצים, אורתופוטו עדכני (WMS), שבילי אופניים, רישוי עסקים, וקווי בניין מהתב"ע.
> פורמט: GeoJSON או Shapefile, ב-ITM או WGS84, עם תאריך עדכון לכל שכבה, וציון אם מותר להציג לציבור.
> תודה.

## מה קורה כשהשכבות מגיעות

1. הקבצים נשמרים ב-`data/` (`streets.geojson`, `quarters.geojson`), ו-`lib/geo.ts` מצייר אותם במפה מעצמו.
2. `npm run import:gis` ממיר אותם לצורה של `lib/city.ts`, ומדווח על כל שם שלא הותאם.
3. מנוע הבדיקה (`run_all_street_audits`) מחשב מחדש, וכל קריטריון שקיבל נתון עובר מ"אין נתון" לציון עם מקור ותאריך.
